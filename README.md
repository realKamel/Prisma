# Prisma

Prisma is an AI-enabled educational management backend built with .NET 10 and ASP.NET Core. It provides APIs for authentication, users, lessons, assessments, assignments, payments, storage, and AI-assisted learning workflows.

## Features

### Identity and access

- Role-based access for students, teachers, assistants, and administrators, with teachers additionally scoping their own assistants.
- JWT bearer authentication with refresh tokens, HTTP-only cookie support, and refresh-token revocation backed by Valkey.
- Permission-scoped assistant accounts managed per teacher.
- Email verification, forgot/reset password with confirmation codes, and profile/password self-service.
- Account lockout, email verification, and configurable password policies (relaxed in Development, strict in Production).

### Learning content

- Academic years, lessons, sections, and lesson materials attached to a teacher's catalog.
- Lesson editor supporting multipart material uploads, thumbnail/public assets, and lesson lifecycle toggling.
- Video playback through Mux, including signed playback tokens, upload URLs, audio URLs, and webhook handling.
- Per-student section progress tracking (start, save watched seconds, complete) and lesson status.
- Lesson transcripts with chunking, embeddings, and AI-generated summaries produced by background jobs.

### Assessments and assignments

- Quizzes composed of multiple-choice, true/false, and written questions, authored per lesson and academic year.
- Exam extraction from uploaded PDFs using PdfPig, with an extraction job queue and status polling.
- Student quiz attempts with autosave, submission, results, and anti-cheat security events.
- AI-assisted grading of written answers with grading suggestions, teacher overrides, and score locking.
- Assignments and submissions with paged, searchable listing, grading, notes, and grading-lock release.
- Grade options and grade retrieval for students and teachers.

### AI capabilities

- RAG chat over lesson content using retrieval tools, embeddings, and vector search (`pgvector`).
- Server-Sent Events (SSE) streaming of assistant responses with per-user concurrency limits.
- Microsoft Agent Framework agents for chat, grading, and knowledge RAG, configured with keyed chat/embedding clients.
- Agentic workflows for written-question grading and weekly report generation.
- Weekly AI student reports generated by a recurring Hangfire job.

### Commerce and enrollment

- Lesson access grants, enrollment, redeem-code batches, and per-student lesson grants.
- Paymob card and Fawry payment initiation with HMAC-verified webhooks and payment history.
- Teacher finances, platform statistics, and student performance/history dashboards.

### Platform and operations

- Feature flags via `Microsoft.FeatureManagement` for AI grading, RAG chat, and weekly reports.
- English (`en-US`) and Arabic (`ar-EG`) localization with localized result messages.
- Hybrid caching (in-memory + Valkey with backplane), Redis-backed distributed output caching, and fail-safe/stale-while-revalidate behavior.
- Multiple Redis-backed rate-limiting policies for auth, public, per-user read/write, and LLM streaming endpoints.
- Serilog structured logging, OpenTelemetry traces and metrics, Prometheus scraping, and health probes.
- API versioning with per-version OpenAPI documents, Swagger UI, and typed `Ardalis.Result` responses.
- Admin dashboards, activity logs, audit logs, and platform configuration.
- Docker Compose stack with PostgreSQL/pgvector, Valkey, PgBouncer, MinIO, and an optional observability profile.

## Architecture

The solution follows Clean Architecture and separates the web layer, use cases, domain rules, and infrastructure integrations.

```text
+--------------------------------------------------+
|                    Prisma.API                    |
|        Presentation / HTTP and Web Layer         |
|   Controllers, middleware, filters, OpenAPI      |
+--------------------------+-----------------------+
						   |
+--------------------------v-----------------------+
|                Prisma.Application                |
|              Use Cases / Business Logic          |
|    MediatR commands, queries, validation, DTOs   |
+--------------------------+-----------------------+
						   |
+--------------------------v-----------------------+
|                  Prisma.Domain                   |
|               Enterprise Business Rules          |
|     Entities, value objects, interfaces, rules   |
+--------------------------^-----------------------+
						   |
+--------------------------+-----------------------+
|             Prisma.Infrastructure                |
|       Persistence and External Integrations      |
| EF Core, Identity, Hangfire, AI, storage, email  |
+--------------------------------------------------+
```

| Project | Responsibility |
| --- | --- |
| `Prisma.API` | ASP.NET Core API, controllers, middleware, filters, authentication, health endpoints, and OpenAPI UI. |
| `Prisma.Application` | Application use cases, MediatR commands and queries, validation, and application contracts. |
| `Prisma.Domain` | Entities, value objects, enums, errors, interfaces, repositories, and specifications. |
| `Prisma.Infrastructure` | EF Core persistence, Identity, Hangfire, caching, storage, payments, video, email, and AI integrations. |
| `Prisma.Application.Tests` | Unit tests for application behavior. |
| `Prisma.Integration.Tests` | API and persistence integration tests using ASP.NET Core testing and Testcontainers PostgreSQL. |

Requests flow through thin controllers that dispatch MediatR commands and queries. Handlers return `Ardalis.Result` values that are translated to HTTP responses by a default result convention, with FluentValidation running in a MediatR pipeline behavior and localized result messages applied by a filter. Features are organized vertically: each `Features/<Area>` folder holds its own commands, queries, DTOs, and specifications.

## Technology

- **Runtime and data:** .NET 10 (`net10.0`), ASP.NET Core, Entity Framework Core 10 with Npgsql, PostgreSQL 18 with `pgvector`, and Valkey/Redis-compatible caching.
- **Application patterns:** MediatR, FluentValidation, `Ardalis.Result` (+ ASP.NET result conventions), Ardalis Specification, and ASP.NET Core Identity.
- **Security:** JWT Bearer authentication, refresh-token revocation, cookie support, permission-based authorization, and API versioning (`Asp.Versioning`).
- **Background processing:** Hangfire with PostgreSQL storage, dedicated queues (default, reports, video processing, auth cleanup), and recurring jobs.
- **AI and agents:** Microsoft Agent Framework (Agents, Workflows, Hosting), Microsoft.Extensions.AI, OpenAI SDK (GitHub Models inference endpoint), Groq SDK, Semantic Kernel, and `Microsoft.Extensions.VectorData`.
- **Integrations:** Mux for video, AWS SDK for S3-compatible object storage (MinIO locally), MailKit for email, and Paymob (card and Fawry) for payments.
- **Caching and resilience:** FusionCache hybrid cache (in-memory + Valkey backplane) with fail-safe and soft/hard timeouts, distributed output caching, and `RedisRateLimiting`.
- **Observability and diagnostics:** Serilog (compact JSON), OpenTelemetry traces/metrics with OTLP and Prometheus exporters, health checks, and OpenAPI/Swagger.
- **Documents:** PdfPig for PDF text extraction.
- **Testing:** xUnit, NSubstitute, FluentAssertions, `Microsoft.AspNetCore.Mvc.Testing`, Testcontainers PostgreSQL, and coverlet.

## Configuration

Local configuration can be supplied through .NET user secrets, environment variables, or a local `.env` file used by Docker Compose. The main configuration sections are:

| Section | Purpose |
| --- | --- |
| `ConnectionStrings` | PostgreSQL (`DefaultSqlConnection`) and Valkey (`Valkey`) connections. |
| `deploymentUrls` | Backend and frontend URLs used in email links and redirects. |
| `JwtSettings` and `IdentitySeed` | Authentication settings and development admin seed data. |
| `OpenAI` and `Groq` | Chat, reasoning, embedding, and speech models plus API credentials. |
| `Mux` | Video access, signing, and webhook credentials. |
| `ObjectStorage` and `VideoStorage` | S3-compatible storage configuration and public asset prefixes. |
| `PaymobSettings` | Payment gateway credentials, card/Fawry integration IDs, and callback URLs. |
| `EmailSettings` | SMTP configuration. |
| `FeatureManagement` | Feature flags for AI grading, RAG chat, and weekly AI reports. |
| `RateLimitSettings` | Auth, public, per-user read/write, and LLM concurrency limits. |
| `Serilog` | Logging levels, enrichers, and sinks. |

## Run Locally

Start the local infrastructure first:

```bash
docker compose up -d
```

The Compose stack includes:

- PostgreSQL 18 with the pgvector extension (`db`), bound to `localhost:5432`.
- Valkey cache (`cache`), bound to `localhost:6379`.
- PgBouncer connection pooling (`connection-pooler`), bound to `localhost:6432`.
- MinIO S3-compatible object storage in the development override, with its console at `http://localhost:9001`.

An optional observability profile adds Prometheus, Grafana, Loki, Alloy, Tempo, and infrastructure exporters (node, cAdvisor, Postgres, PgBouncer, and Valkey). Start it with:

```bash
docker compose --profile observability up -d
```

Then restore and run the API:

```bash
dotnet restore
dotnet run --project Prisma.API
```

The development launch profiles expose the API at:

- HTTP: `http://localhost:5117`
- HTTPS: `https://localhost:7109`
- OpenAPI/Swagger UI: `/swagger`

Application data seeding runs during startup, including roles and the seeded admin account. The API also exposes `/health/live` for liveness and `/health/ready` for readiness (PostgreSQL, Valkey, and Hangfire) checks. The Hangfire dashboard is available at `/hangfire`, and Prometheus metrics are scraped from the metrics endpoint.

## API

All controllers use the versioned `/api/v{version}/[controller]` route pattern (currently `v1`), with some teacher- and student-facing controllers exposing explicit prefixes such as `/api/v1/teacher/...` and `/api/v1/student/...`. The main endpoint groups are:

| Area | Controllers |
| --- | --- |
| Authentication and users | `AuthController`, `UsersController`, `PreferencesController` |
| Student and teacher workflows | `StudentsController`, `TeachersController`, `TeacherStudentsController` |
| Assistant management | `AssistantsController` |
| Administration | `AdminController`, `PlatformConfigurationsController` |
| Learning content | `LessonsController`, `SectionProgressController`, `LandingPageController` |
| Assessments | `TeacherQuizzesController`, `StudentQuizzesController`, `GradingController`, `GradesController` |
| Assignments | `TeacherAssignmentsController` |
| AI and RAG | `RagController` |
| Payments and access | `PaymentsController`, `CodesController` |
| Files and video | `StorageController`, `VideoStorageController` |

Handlers return typed `Ardalis.Result` values that are translated into appropriate HTTP status codes, with per-version OpenAPI documents and Swagger UI enabled in the Development environment. The RAG chat endpoint streams token-by-token responses over Server-Sent Events.

## Reliability, Caching, and Rate Limiting

- **Hybrid caching:** FusionCache combines an in-memory L1 with a Valkey-backed L2 and a Redis backplane so all API nodes stay consistent. Entries use fail-safe, soft/hard factory timeouts, and jittered expiration to protect against cache stampedes and database outages.
- **Output caching:** Distributed output caching is registered and applied to eligible endpoints.
- **Rate limiting:** Redis-backed policies protect the API, returning `429` with `Retry-After` and problem details when exceeded:
  - `Auth` — sliding window per IP for login, register, and refresh.
  - `Public` — token bucket per IP for public catalogs and preferences.
  - `UserRead` — token bucket per authenticated user (default policy for controllers).
  - `UserWrite` — stricter token bucket per user for costly writes.
  - `LlmConcurrency` — concurrency limit per user for streaming LLM endpoints.
- **Health checks:** `/health/live` runs lightweight checks, while `/health/ready` includes tagged PostgreSQL, Valkey, and Hangfire checks.
- **Feature flags:** AI grading, RAG chat, and weekly reports can be toggled per environment through `FeatureManagement`.

## Observability

- **Logging:** Serilog writes compact JSON to the console with machine/thread enrichers and exception details, and supports Seq plus the Loki/Alloy pipeline.
- **Tracing:** OpenTelemetry traces ASP.NET Core requests, outgoing HTTP calls, and EF Core queries, exporting via OTLP to Tempo.
- **Metrics:** OpenTelemetry collects ASP.NET Core, HTTP client, and runtime metrics and exposes them through the Prometheus exporter.
- **Dashboards:** The optional `observability` Compose profile provisions Grafana with Prometheus, Loki, and Tempo, alongside node, cAdvisor, PostgreSQL, PgBouncer, and Valkey exporters.

## Database and Migrations

The application uses PostgreSQL through Entity Framework Core. Database initialization and application data seeding are performed at startup. When migrations are added, use:

```bash
dotnet ef migrations add <MigrationName> \
	--project Prisma.Infrastructure \
	--startup-project Prisma.API

dotnet ef database update \
	--project Prisma.Infrastructure \
	--startup-project Prisma.API
```

## Testing

Unit tests cover application handlers and behaviors, while integration tests exercise the API and persistence layers through `WebApplicationFactory` and Testcontainers PostgreSQL.

```bash
dotnet test Prisma.Application.Tests
dotnet test Prisma.Integration.Tests
```

To build the complete solution:

```bash
dotnet build Prisma.sln
```
